Branch `ci/dev-fdroid-repo`. Each implementation task is a brief for the `implementer` sub-agent. Layer rule: build and CI tooling only; no change to UI, State, Platform, Bindings or Core code. **The owner steps in §4 come before the merge** (design, Risks: merge order).

## 1. Dev version and identity (build-logic, app, scripts)

- [x] 1.1 **Dev version function.** Goal: `AndroidVersion.devVersion(base: String, committerEpoch: String?, commit: String?)` returns `(versionName, versionCode)` as design §2: separator `.` when `base` has a pre-release part, `-` otherwise; `dev.<yyyyMMddHHmmss UTC>+<sha8>`; code = epoch − 1_767_225_600. Validation: epoch digits only; commit cut to 8 characters, lowercase hex. Missing or invalid input, an epoch before 2026-01-01 or a code above 2_100_000_000 → code 1 and `…dev.0+unknown`, plus a Gradle warning at the call site (never a failed build). Files: `apps/android/build-logic/src/main/kotlin/org/guardedsleep/buildlogic/AndroidVersion.kt`, `…/src/test/…/AndroidVersionTest.kt`. Acceptance: tests cover both separators, the example `0.1.0-alpha.1` at 2026-11-19 14:30:12 UTC with commit `abc12345ff` → `0.1.0-alpha.1.dev.20261119143012+abc12345`, ordering of two epochs, every fallback case; the `versionCode(versionName)` tests stay unchanged and green.
- [x] 1.2 **Commit epoch into the build.** Goal: `scripts/gradle.sh` exports `GS_GIT_COMMIT_EPOCH` (`git log -1 --format=%ct`, host side, passed into the container like the other `GS_GIT_*`). Files: `scripts/gradle.sh`. Acceptance: shell lint clean; the variable reaches Gradle in the container.
- [ ] 1.3 **Debug variant identity.** Goal: in `apps/android/app/build.gradle.kts`, `androidComponents.onVariants(selector().withBuildType("debug"))` sets `applicationId` to `org.guardedsleep.app.dev` and sets `versionCode`/`versionName` on every output from 1.1, reading `GS_GIT_COMMIT_EPOCH` and `GS_GIT_COMMIT` through `providers.environmentVariable`; no `afterEvaluate`; release unchanged; comment with the AGP variant API doc link. Acceptance: `aapt2 dump badging` on the debug APK shows `org.guardedsleep.app.dev` and the dev version; on the release APK `org.guardedsleep.app.alpha` and `versionCode=100101`; `just verify-android` (JVM tests, Roborazzi) green with unchanged baselines.
- [ ] 1.4 **Dev label and icon.** Goal: a non-critical locale key `native.appNameDev` = "GuardedSleep Dev" in `locales/en.json`, used as the debug launcher label via `src/debug/AndroidManifest.xml` (`tools:replace="android:label"`); `src/debug/res/values/ic_launcher_background.xml` with a clearly different colour (comment: launcher colour, not copy); a debug `ic_launcher_monochrome.xml` with a small corner badge (design §9). Check Settings → About on a narrow screen with the long dev `versionName` (design §8). Acceptance: `just gen` generates the key; the literal lint passes; the owner sees label, colour and themed-icon badge on a device (4.3).
- [ ] 1.5 **Package id everywhere.** Goal: `org.guardedsleep.app.dev` in `scripts/poc/gate.sh` (`PKG`), `scripts/android-install.sh` (`PKG`, plus `adb install -r -d` and a help line about downgrades, design §8), `apps/android/maestro/*.yaml` (`appId`), the KDoc examples in `DebugInjectReceiver.kt` and `DebugTalkReceiver.kt`, `docs/contributing/turn-server-vps.md`, `docs/contributing/alpha-hardware-test.md`. The debug broadcast action strings stay. Acceptance: `git grep -n "org.guardedsleep.app.alpha" -- ':!openspec/changes/archive' ':!CHANGELOG.md'` lists only the release id in `app/build.gradle.kts`, the action strings, `scripts/poc/release-check.sh`, `scripts/poc/release-permissions.txt`, AGENTS.md and the specs; `DOZE_MINUTES=2 just gate` passes locally or in CI.

## 2. Pre-release, repository and Pages (CI)

- [ ] 2.1 **`dev-apk` changes.** Goal (design §6): delete `dev.p12` right after `apksigner sign` (the `always()` step stays); read `versionName`/`versionCode` with `aapt2 dump badging`; title and notes use the `versionName`; notes link the F-Droid repository and explain the one-time migration and the asset rename (design §8); asset renamed to `guardedsleep-dev.apk` (+ `.sha256`, and the old asset deleted from the release once); upload the re-signed APK as a workflow artifact. No repository secret check in this job. Files: `.github/workflows/android-native.yml`. Acceptance: `just lint-workflows`.
- [x] 2.2 **Locked fdroidserver.** Goal (design §6): `tools/fdroid/requirements.in` (`fdroidserver==2.4.5`, comment with the PyPI link), `requirements.txt` from `uv pip compile --generate-hashes`, and `build-constraints.txt` with hashes for the build backend of source-only packages (`setuptools`, `wheel`), all with the pinned uv from mise; Renovate `pip-compile` manager in `renovate.json` with explicit `managerFilePatterns` for both files (own group, no automerge). Acceptance: `uv pip install --require-hashes --build-constraints tools/fdroid/build-constraints.txt -r tools/fdroid/requirements.txt` into a scratch venv works and `fdroid --version` prints 2.4.5; the same install with `--no-build` fails only on `clint` (proves which package is built); Renovate config validation (`npx --yes renovate-config-validator` or the check `just lint` runs) passes and matches both files.
- [ ] 2.3 **`dev-repo` job.** Goal (design §4, §6): `needs: dev-apk`, environment `dev-repo`, `permissions: { contents: read }`, no `GH_TOKEN`; check the three `GS_DEV_REPO_*` secrets (fail naming the missing one); install from 2.2 with `--require-hashes`; write `config.yml` (keys listed in design §6) and the keystore into `$RUNNER_TEMP`; fetch previous builds per design §4 (`jarsigner -verify -strict` and `keytool -printcert -jarfile` on `entry.jar` against `GS_DEV_REPO_FINGERPRINT` from the workflow `env:`, `entry.json` → SHA-256 of `index-v2.json`, only codes lower than the new one, APK SHA-256 from that index and `apksigner verify --print-certs` against the dev certificate, fresh start with a warning on any failure); name APKs `org.guardedsleep.app.dev_<versionCode>.apk`; generate the metadata file; `fdroid update`; `archive_older: 0`; delete the keystore; upload the site root containing `fdroid/dev/repo/` with `actions/upload-pages-artifact`. Put the logic in a script (`scripts/dev-fdroid-repo.sh`) so it can run locally. Acceptance: `just lint-workflows`; local runs of the script in a scratch directory with a throwaway key against the current `android-dev` APK: (a) a fresh repository, (b) a second run with a higher fake code keeps both, (c) a re-run with the same code lists it once, (d) a tampered `entry.jar` leads to a fresh start.
- [ ] 2.4 **`dev-pages` job.** Goal (design §6): `needs: dev-repo`, environment `github-pages`, `pages: write` + `id-token: write` on the job only, concurrency `pages` without cancel, `actions/deploy-pages` SHA-pinned. Acceptance: `just lint-workflows`; `permissions: {}` stays the workflow default.
- [x] 2.5 **Repo key script.** Goal: `scripts/dev-repo-key.sh` modelled on `scripts/dev-apk-key.sh` (design §5): PKCS12 key with `keydname`, environment `dev-repo` limited to `main`, the three secrets, Bitwarden item, no overwrite without `GS_ROTATE_DEV_REPO_KEY=1`, no secret printed; prints the public SHA-256 certificate fingerprint. Acceptance: shell lint clean; header comment explains usage.
