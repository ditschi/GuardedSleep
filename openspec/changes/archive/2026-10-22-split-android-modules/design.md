# Design

## Context

Source: ADR-020 §4 (build, formatting and lint, release build), AGENTS.md §5.1 (UI renders contract models only; in Android only `platform` may depend on `core-bindings`).

## Decisions

- **Module boundaries enforce the layers**: a UI import of an FFI type becomes a compile error instead of a review finding.
- **Manual constructor DI**, no Hilt.
- **Dependency graph** (Gradle `implementation`, so nothing leaks transitively): `app` -> `ui-contract`, `platform`; `platform` -> `ui-contract`, `core-bindings`; `ui-contract` and `core-bindings` depend on no project module. Kotlin packages stay `org.guardedsleep.app.*` in every module (the move is a pure rename with history, no import churn); only the Android namespaces differ (`org.guardedsleep.app`, `.app.contract`, `.app.platform`, `org.guardedsleep.core`).
- **Where things live:** `ui-contract` holds `UiContract.kt` and the generated string catalogue (both `app` and `platform` need `R.string.*`: screens and notifications). `platform` holds the monitor service (with its manifest entry), alerts, silence, link, media (`media/libwebrtc`), signaling, pairing, readiness, settings and config. `app` holds `Application`, the activities and receiver, the Compose UI, the debug source set and `AppGraph`.
- **Platform never imports `app`:** `platform` declares `EntryPoints` (main activity, alert activity and action receiver classes), `AlertIntents` (extras and actions) and `PlatformServices`/`PlatformServicesProvider`; `app` implements them (`AppEntryPoints`, `AppGraph`, `GuardedSleepApp`). The monitor service finds its graph through the application object.
- **No UniFFI type in a `platform` signature that `app` calls:** the media factory takes the contract `Role` (was the UniFFI `Role`), so `app` wires `LibWebRtcMediaEngine` without seeing `core-bindings`.
- **Boundary proof (task 1.3):** a temporary `import uniffi.guardedsleep_core.LinkState` in `MainActivity` fails `:app:compileDebugKotlin` with `Unresolved reference 'uniffi'`; reverted. `BindingSeamTest` (in `platform`, next to `MediaEngineSeamTest`) keeps the boundary from eroding: it fails on a `uniffi.` import outside `platform` and `core-bindings`, on a `project(":core-bindings")` in any other module or `api(project` in `platform`, and when it sees no sources.
- **Contract properties cannot be smart-cast across modules** (public API of another module); the screens copy them into local `val`s.
- **Tests follow their code:** the logic, mapping, pairing, link and `MediaEngineSeamTest` tests moved to `platform` (host `.so` via `jna.library.path` = `target/debug`), `ConformanceTest` stays in `core-bindings`, the Compose/Roborazzi tests stay in `app` with their baselines untouched. `MediaEngineSeamTest` scans every source set (`main`, `debug`, `test`, ...) of every module and fails if it cannot see the `debug` source set (critical-review finding N2 of `swap-webrtc-sdk`).
- **build-logic** is an included build with class-based convention plugins (`guardedsleep.android-application`, `.android-library`, `.compose`, `.kotlin`, `.i18n`); class-based rather than precompiled script plugins so the Android DSL types are explicit and no accessor generation depends on AGP 9's built-in Kotlin.
- **Lint (task 2.2):** `warningsAsErrors` and `abortOnError` in the convention plugin, no baseline. First run: 3 findings in `core-bindings`, 22 in `platform`, 17 + 1 hint in `app`. Fixed: missing permissions (declared in the `platform` manifest, where the calls are), `NewApi` on the Zen rule (`@RequiresApi(Q)` on the only caller path that is already behind an SDK check), `setShowWhenLocked`/`setTurnScreenOn` on API 26 (real crash: now an SDK check with window-flag fallback, manifest `tools:targetApi`), `UseKtx` (`toUri`), `Configuration.screenWidthDp/HeightDp` (window size via `LocalWindowInfo`; Roborazzi baselines unchanged), `mutableIntStateOf`, backup (`dataExtractionRules` and `fullBackupContent` that exclude everything, as `allowBackup=false` is not enough on Android 12+), missing application icon (a placeholder vector until the brand asset exists). Suppressed with a reason: `InlinedApi` for the foreground-service types and `TYPE_BLE_HEADSET` (inlined ints), `WakelockTimeout` (lock lives exactly as long as the foreground service), `BatteryLife` (Doze exemption is the point of the feature), `CustomSplashScreen` (debug trampoline without a window), `NewApi` in the generated UniFFI file (`core-bindings/lint.xml`, UniFFI falls back below API 33). Review fixes: the `NewApi` ignore in `core-bindings/lint.xml` is narrowed to `java.lang.ref.Cleaner` in the generated file, the `InlinedApi` reason on `foregroundType` is corrected (the manifest declares the same bits, so the API 29 subset check passes), and the `device_*` backup domains are excluded too. `GradleDependency`/`NewerVersionAvailable` are disabled: they need the network and Renovate owns freshness. `just verify-android` runs `lintDebug` in every module.
- **versionCode (task 2.4):** `apps/android/version.properties` holds `versionName`; the `guardedsleep.android-application` plugin derives `versionCode = major*10_000_000 + minor*100_000 + patch*1_000 + stage*100 + n` with stage alpha=1, beta=2, rc=3, release=9 (and n=0 for a release), implemented once in `build-logic` (`AndroidVersion`) and tested (`buildLogicTest`, part of `just test-android` and `verify-android`). `0.1.0-alpha.1` gives 100101 (the installed alpha builds had code 1, so they upgrade), `0.1.0` gives 100900. Limits: minor, patch and n at most 99, major at most 209 so the code stays below Google Play's 2_100_000_000; a name outside `MAJOR.MINOR.PATCH[-(alpha|beta|rc).N]` fails the build.
- **R8 (task 2.3):** `isMinifyEnabled` and `isShrinkResources` on for `release`. The keep rules are the `consumer-rules.pro` of the module that owns the dependency, so they travel with it: `core-bindings` keeps `uniffi.**` and `com.sun.jna.**` (JNA reaches classes, Structure fields and callbacks by name; its AAR ships no rules), `platform` keeps `org.webrtc.**` and native methods (the `io.github.webrtc-sdk:android` AAR ships no rules; zxing-cpp ships its own). The rules are broad on purpose: a missing keep shows up only at runtime, and the emulator gate drives the debug APK, so a narrow rule could not be proven. **Release APK size** (`app-release-unsigned.apk`, arm64-v8a + x86_64): 48_080_061 bytes before, 36_944_763 bytes after (minus 11.1 MB, minus 23 percent; `classes*.dex` 35.0 MB to 4.2 MB, `resources.arsc` 897 KB to 374 KB, native libraries unchanged). `release-check.sh` and `size-check.sh` pass (core adds 1_697_968 bytes). Review fixes: `core-bindings/consumer-rules.pro` adds `-keepattributes *Annotation*,Signature,InnerClasses,EnclosingMethod` and the native-method rule in `platform` is scoped to `org.webrtc.**`. `release-check.sh` now also compares the merged release-manifest permissions with `scripts/poc/release-permissions.txt` and fails on any extra one. Not covered (open, task 1.6 of `add-android-release` blocks the first distributed release APK): starting the release build on a device (it has no debug hooks for the gate); the dex was checked for `uniffi.guardedsleep_core.CoreLink`, `org.webrtc.PeerConnectionFactory`, `com.sun.jna.Native` and `zxingcpp.BarcodeReader`.
- **Review fixes (not done):** the placeholder launcher icon stays a plain vector until the brand asset exists (then an adaptive icon). A separate `:strings` module is the fallback if `ui-contract` must ever become a pure-JVM module; the generated string catalogue lives in `ui-contract` today because both `app` and `platform` need it. The version regex rejects leading zeros and `alpha.0`.
- **Discarded alternatives:** one module with lint rules (violations found late); Hilt (annotation processing, harder for agents to follow).
