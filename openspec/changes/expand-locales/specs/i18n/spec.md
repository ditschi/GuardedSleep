# Spec Delta

## MODIFIED Requirements

### Requirement: Shipped locales are complete

A locale SHALL be generated and shipped only when every key tagged `critical` (alerts, link loss, connection state, safety warnings) is present with the same placeholders and all CLDR plural categories of its language; other keys MAY fall back to English. The shipped set SHALL be en, de, fr, es, it, pt, nl, pl, sv, da, cs, ro, zh-Hans, ja, ko, hi, ar, tr, uk and id, and further locales MAY be added the same way.

#### Scenario: Missing German key

- **WHEN** a key tagged `critical` exists in `en.json` but not in `de.json`
- **THEN** the catalogue check fails and names the missing key

#### Scenario: Missing critical key

- **WHEN** a locale lacks the translation of a link-loss alert key
- **THEN** the generator does not ship that locale

#### Scenario: Missing non-critical key

- **WHEN** a locale lacks a settings label
- **THEN** that label falls back to English and the locale still ships

## ADDED Requirements

### Requirement: Review markers

Every non-English value SHALL carry a `machineTranslated` or `reviewed` marker; review SHALL NOT gate shipping.

#### Scenario: New machine translation

- **WHEN** a new locale is generated by AI translation
- **THEN** its values are marked `machineTranslated`

### Requirement: Right-to-left and layout checks

The generator SHALL produce an RTL pseudo-locale, enforce length budgets on critical keys, and the Android build SHALL list exactly the generated locales; screenshot and overflow tests SHALL cover German and Arabic.

#### Scenario: Alert text too long in German

- **WHEN** a German critical value exceeds its length budget
- **THEN** generation fails

### Requirement: Core message keys exist

Every key returned by the core's `message_keys()` SHALL exist in `locales/en.json`, checked by `just lint`.

#### Scenario: New core message key

- **WHEN** the core adds a message key without a catalogue entry
- **THEN** `just lint` fails
