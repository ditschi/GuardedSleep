# i18n Specification

## Purpose

Keep all user-visible copy in one catalogue with English as the master, ship only complete languages, and turn the catalogue into platform resources by a checked generator, so no screen or alarm shows hard-coded or mixed-language text. Migrated from ADR-020 §7 and ADR-021 §2, as built.

## Requirements

### Requirement: One catalogue

All user-visible copy SHALL live only in `locales/*.json`, with English (`en`) as the master. Values SHALL use the ICU plural and select subset with named placeholders. The core SHALL emit message keys, never prose.

#### Scenario: New screen text

- **WHEN** a developer adds text to a screen
- **THEN** the text is added as a key in `locales/en.json` and the UI refers to that key

### Requirement: No literals in UI code

A lint SHALL fail when Android Compose UI code passes a string literal as text, label or content description; empty strings and test tags are allowed.

#### Scenario: Hard-coded button label

- **WHEN** Compose code contains `Text("Start")`
- **THEN** the lint fails

### Requirement: Shipped locales are complete

A locale SHALL be generated and shipped only when every key tagged `critical` (alerts, link loss, connection state, safety warnings) is present with the same placeholders and all CLDR plural categories of its language; other keys MAY fall back to English. The shipped set SHALL be en, de, fr, es, it, pt, nl, pl, sv, da, cs, ro, zh-Hans, ja, ko, hi, ar, tr, uk and id, and further locales MAY be added the same way.

#### Scenario: Missing German key

- **WHEN** a key tagged `critical` exists in `en.json` but not in `de.json`
- **THEN** the catalogue check fails and names the missing key

#### Scenario: Missing critical key

- **WHEN** a locale lacks the translation of a link-loss alert key
- **THEN** the generator does not ship that locale

#### Scenario: Missing non-critical key

- **WHEN** a locale lacks a settings label
- **THEN** that label falls back to English and the locale still ships

### Requirement: Generated resources

A generator SHALL produce Android string and plural resources and a web catalogue (including an accented pseudo-locale for layout testing) from the catalogue. Generated output SHALL NOT be committed.

#### Scenario: Fresh checkout

- **WHEN** someone builds the app from a fresh checkout
- **THEN** the build generates the platform resources from `locales/*.json`

### Requirement: Spellchecking

English text SHALL be spellchecked by `typos`, and non-English catalogues by CSpell with per-language dictionaries.

#### Scenario: Typo in German copy

- **WHEN** a German catalogue value contains a misspelled word
- **THEN** the CSpell check reports it

### Requirement: Language choice

The user SHALL be able to follow the system language or choose one of the shipped languages in the app's settings.

#### Scenario: German phone, English preferred

- **WHEN** a user on a German system selects English in the app
- **THEN** the app shows English copy

### Requirement: Critical tags

The keys tagged `critical` and their length budgets SHALL be listed in one file, `locales/critical.json`, by exact key or group prefix. The catalogue check SHALL fail when a listed pattern matches no key in `en.json`.

#### Scenario: Renamed alert key

- **WHEN** a change renames a critical key in `en.json` without updating `locales/critical.json`
- **THEN** the catalogue check fails and names the stale pattern

### Requirement: Review markers

Every non-English value SHALL carry a `machineTranslated` or `reviewed` marker; review SHALL NOT gate shipping.

#### Scenario: New machine translation

- **WHEN** a new locale is generated by AI translation
- **THEN** its values are marked `machineTranslated`

### Requirement: Right-to-left and layout checks

The generator SHALL produce an RTL pseudo-locale, enforce length budgets on critical keys, and the Android build SHALL list exactly the generated locales; screenshot and overflow tests SHALL cover German and Arabic.

#### Scenario: Alert text too long in German

- **WHEN** a German critical value exceeds its length budget
- **THEN** generation fails

### Requirement: Core message keys exist

Every key returned by the core's `message_keys()` SHALL exist in `locales/en.json` as `core.<camelCase key>` (for example `server_unreachable` as `core.serverUnreachable`), checked by `just lint`.

#### Scenario: New core message key

- **WHEN** the core adds a message key without a catalogue entry
- **THEN** `just lint` fails

### Requirement: No unused keys

Every key in `locales/en.json` SHALL be used by the Android or web client or returned by the core's `message_keys()`, checked by `just lint`.

#### Scenario: Screen removed

- **WHEN** a change deletes the last use of a key
- **THEN** `just lint` fails until the key is removed from every catalogue
