# Browser E2E (`@guardedsleep/e2e`)

Playwright tests that spin up **two Chromium instances** (baby + parent) against `just dev` (Rust signaling server + the Vite dev server of `apps/web`; see `scripts/dev.sh`). Audio input uses Chromium fake devices and WAV fixtures under `tests/fixtures/` (generated by `pnpm run generate-fixtures`). Tests select by the stable `snake_case` test ids of `docs/technical/alpha-ux-flows.md` section 4, never by copy text.

## Prereqs

- the mise-pinned Node and pnpm (`just setup`)
- `pnpm install` at repo root (installs Playwright in this workspace)
- First run: `pnpm --filter @guardedsleep/e2e exec playwright install chromium` (CI uses `--with-deps`)

Playwright starts `just dev` with **`PORT=18787`** for the signaling server so it does not fight a developer stack on **8787**. The pages learn that address from `E2E_SIGNALING_URL` (set in `playwright.config.ts`): the baby device through the settings screen, the parent device from the pairing code.

To reuse an already-running dev stack (you must use the **same** signaling port as in `E2E_SIGNALING_URL`), set `PW_REUSE_EXISTING_SERVER=1` when running Playwright.

## Commands

```bash
just e2e                      # the supported entry point
pnpm --filter @guardedsleep/e2e test
```

With visible browsers (local debugging):

```bash
HEADLESS=0 pnpm --filter @guardedsleep/e2e test
```

## Coverage (high level)

The pairing key lives in page memory only, so tests navigate client-side after pairing and never reload (except where the reload is the point). `utils/web.ts` holds the shared steps (`pairWeb`, `showCode`, `pasteCode`, `expectNoAxeViolations`).

- **20:** pairing screens (QR, copy, paste errors, camera only on request, microphone refused).
- **21:** storage test: no key, invite or room id in any web storage, also after a reload.
- **22 / 23:** monitoring screens; noise alert, silence and a short blip (no alert), link alarm.
- **24:** settings. **25:** wake lock. **26:** night screen. **27:** background loss and resume from sleep.
- **28:** Content-Security-Policy on the production build served by `guardedsleep-server --serve-web`.
- **29:** audio: the gate opens for Listen and for a noise alert, and closes again.
- **30:** link: wrong key, unreachable server, dead first address, dropped DataChannel, outages of the parent (20 s and 90 s).

The signaling server runs with `SIGNALING_HELLO_RATE_PER_MIN=0` and `SIGNALING_NEW_ROOM_RATE_PER_MIN=0` (see `playwright.config.ts`); it caps rooms at one baby and one parent.

## Other commands

The hybrid Android + browser E2E was removed in wave 1 (ADR-020); the native app is covered by the emulator gate (`scripts/poc/local-gate.sh`). The LAN-IP browser check was removed with the legacy client: the offline LAN topology (`add-offline-lan`) is not built yet and brings its own check.

```bash
just diagnose-lan                         # reachability checklist for phone tests
bash scripts/e2e-local-automation.sh      # Docker-first, host-independent browser path
just e2e-docker                           # Linux + Docker only
just check-kvm
```

See [docker/e2e-local](../../docker/e2e-local/README.md) and [docker/android-emulator](../../docker/android-emulator/README.md) for KVM prerequisites and troubleshooting.

## No test hooks in the page

`apps/web` has no `window.__guardedsleep_test` surface. Tests observe the page through its screens and through browser APIs they stub from outside (`utils/browser-stubs.ts`, `utils/rtc.ts`: wake lock, visibility and clock, notifications, CSP violations, WebRTC statistics).

## Privacy

Do not upload Playwright traces that contain pairing codes to public trackers. CI retains traces only on failure as artifacts.
