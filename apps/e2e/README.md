# Browser E2E (`@guardedsleep/e2e`)

Playwright tests that spin up **two Chromium instances** (baby + parent) against `just dev` (Rust signaling server + Vite dev server; see `scripts/dev.sh`). Audio input uses Chromium fake devices and WAV fixtures under `tests/fixtures/` (generated by `pnpm run generate-fixtures`).

## Prereqs

- the mise-pinned Node and pnpm (`just setup`)
- `pnpm install` at repo root (installs Playwright in this workspace)
- First run: `pnpm --filter @guardedsleep/e2e exec playwright install chromium` (CI uses `--with-deps`)

Playwright starts `just dev` with **`PORT=18787`** for the signaling server so it does not fight a developer stack on **8787**. Deep links and `localStorage` (`guardedsleep:signaling-url`) are aligned via `E2E_SIGNALING_URL` set in `playwright.config.ts`.

To reuse an already-running dev stack (you must use the **same** signaling port as in `E2E_SIGNALING_URL`), set `PW_REUSE_EXISTING_SERVER=1` when running Playwright.

## Commands

```bash
pnpm run e2e                 # from repo root

```

## Coverage (high level)

All specs pair through the v3 flow (`utils/pairing.ts` `pairDual`): the baby page shows a code, the parent pastes it on `/pair`. The pairing key lives in page memory only, so tests navigate client-side after pairing and never reload.

- **01–04:** Connect, v3 paste-code pairing, inbound audio after Listen, latency stats (log only).
- **05:** Noise alert reaches the parent (synthetic level via `injectAudioLevel`, microphone levels ignored with `?e2e_synthetic_levels=1`).
- **06 / 07:** Silence and a short blip never alert.
- **08:** After **Listen** off, the baby's outgoing track is disabled.
- **09:** A dropped DataChannel is recovered by the core (new peer connection, no user action).
- **10 / 14 / 15:** Parent audio wiring and inbound RMS for Listen and noise alerts.
- **11:** Wrong PSK = different room: never pairs, parent shows the `peer_absent` cause hint (level 2, about 60 s).
- **12:** Unreachable signaling server: escalation and `server_unreachable` hint.
- **13:** Pairing code with a dead first signaling URL: the driver uses the next one.
- **16:** LAN IP connect. **17:** Standard pairing UX, PSK not in web storage.
- **18:** Recovery: parent offline for 20 s (no level 2) and 90 s (level 2, then restored), each also with the parent page hidden.

The signaling server runs with `SIGNALING_HELLO_RATE_PER_MIN=0` and `SIGNALING_NEW_ROOM_RATE_PER_MIN=0` (see `playwright.config.ts`); it caps rooms at one baby and one parent.

## Dev-only hooks

The mobile app exposes `window.__guardedsleep_test` **only** when `import.meta.env.DEV` is true (Vite dev server). Production static builds must not contain this surface — see [ADR-007](../../openspec/changes/archive/2026-05-13-adr-007-browser-e2e-test-strategy/design.md). On the **parent** route: `getNoiseAlertCount` / `resetNoiseAlertCount`, and `sampleRemoteAudioRms()` for inbound WebRTC RMS sampling. On the **baby** route: `getInviteJson()` (the pairing code) and `injectAudioLevel()`.

## Privacy

Do not upload Playwright traces that contain pasted invites / session pairing material to public trackers. CI retains traces only on failure as artifacts.
