# CI gates

Register of every automated gate, per [ADR-020](../openspec/changes/archive/2026-10-20-adr-020-toolchain-and-development-setup/design.md) §9 and §12. The only required status check on `main` is `ci-ok` (skipped jobs count as passing); everything else feeds into it or runs on its own schedule.

## Budget rule

- Tooling maintenance has a **ceiling of 12 hours per month** (T0 estimate: 7-13 h).
- Every gate has a one-line failure runbook and a last-catch date in the table below. The maintainer owns every gate during alpha. Update "last catch" whenever a gate stops a real defect (not a tooling flake).
- A gate with no catch in **six months** is removed or demoted to nightly.
- When the ceiling is exceeded, the most expensive such gate goes first.
- A test that flakes twice in seven days is quarantined with a tracking issue. Jobs are never retried as a whole.

The maintainer owns every gate during alpha. ### Other safeguards (not CI jobs)

- **Renovate:** dependency freshness within release-age gates; automerge only for test/lint devDependencies and Action digests. Triage the Dependency Dashboard weekly; merge uniffi, wasm-bindgen, the web build chain and gate tools by hand.
- **libwebrtc CVE watch (monthly, manual):** WebRTC-path CVEs (audio codecs, DTLS/SRTP, SCTP, ICE/STUN, SDP) that Chrome stable fixed are also fixed in the `io.github.webrtc-sdk:android` release we ship. First week of each month: compare the Chrome stable security notes since the shipped milestone with the webrtc-sdk release; a critical or exploited CVE unpatched 30 days after the Chrome fix opens a change per the dev-toolchain "libwebrtc patch policy". Record the result in the CVE watch log of the `docs/backlog.md` entry "libwebrtc CVE decision" (or its successor).

## Notes

- **Sans-IO bans and dependency count (`just deny`).** `deny.core.toml` and `.core-dep-count` (48 unique normal dependencies, repeats marked `(*)` by cargo tree deduplicated) look at the all-features graph of `guardedsleep-core`; `deny.core.toml` also bans tokio, mio, getrandom and socket crates from the `guardedsleep-relay` graph. The UniFFI and wasm-bindgen glue lives in `guardedsleep-ffi` and `guardedsleep-wasm`; the only binding-related feature left in core is the optional `tsify` (enabled by `guardedsleep-wasm` alone), whose dependencies are part of the count.
- **API snapshots (`just api-check`, inside `just lint`).** `scripts/lib/api-snapshot.sh` diffs `cargo public-api` of `guardedsleep-ffi` and `guardedsleep-wasm` (`crates/*/api.txt`) and the generated TypeScript definitions (`packages/core-wasm/api/core.d.ts`) against the committed copies. The nightly is pinned in `tools/nightly/rust-toolchain.toml` and cargo-public-api in `mise.toml` (`[vars]`); both run in a stock Rust container without a host toolchain, so the step prints SKIPPED without Docker (FAILED with `GS_STRICT=1`). Regenerate with `just api-snapshot` and review the diff.
- **Planned gates (ADR-020), not yet in place:** nightly fuzz, WASM and APK size budgets, and the emulator gate as a required check on `android-v*` release builds, and a release smoke (install the R8 release APK on the emulator, no crash or `UnsatisfiedLinkError` at start; tracked in `add-android-release`). Add a row above when each lands.
