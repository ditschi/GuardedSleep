# Full review 2026-11: core, clients, server, toolchain, design

**Date:** 2026-11-10 · **Tree:** `5b88b757` (`fix/web-nginx-no-client-ip-logs`, one commit ahead of `main` at `124fe9f4`) · **Phase:** alpha build-out, before the first `android-v*` tag.

**Purpose.** A complete pass over the product as built: weaknesses, defects and unclear design, with concrete ways to simplify the implementation and to keep the whole setup (devices, project server, toolchain) secure without adding ceremony. Reviews are dated records; findings are closed by linking the PR or change next to them.

**Method.** Seven read-only role reviews (Security & Privacy Architect on the core crypto and on the relay/server/deployment; Technical Architect + Critical Reviewer on the Link state machine, the Android client, the web client and the toolchain; Critical Reviewer + Product Owner on specs and docs). Every finding below cites `file:line` and was verified in the tree; the coordinator re-checked the top code findings by hand. Baseline on this tree: `just test` green (624 cargo tests, WASM conformance, 638 Vitest, Android JVM tests), `just lint-code` and `lint-workflows` green, `openspec validate --all --strict` 19/19, typos, hygiene, REUSE and the secret scan green. `just lint-text` fails only because Prettier scans the untracked `.cursor/` folder (see T5).

**Verdict.** The security core holds: no path was found by which an unauthenticated party can advance `last_alive`, close a trusted attempt, mute escalation or learn a secret, and the test and vector coverage is unusually thorough for an alpha. The weaknesses are at the edges: one Android resume path that can leave the parent service running silently without a link, a web off switch that does not reach the core, a documentation layer that still promises "no server" while the decided default is a project server, and specs that describe a product that no longer exists because finished changes are not archived. None of the code findings needs an architecture change. The biggest simplification wins are in `link.rs` (five interleaved state machines), the legacy `Session`/v2 paths, the duplicated noise-event logic in three places, and the PoC-era Docker recipes that still run in every gate.

Severity: `CRITICAL` = can cause a missed alarm, a secret leak or a false public promise · `IMPORTANT` = spec violation, latent safety or security defect, or a decision the alpha release depends on · `MINOR` = hardening, hygiene · `INFO` = note. Effort: S < 1 day, M 1–3 days, L a change with its own tasks.

## 3. Rust core: Link state machine (Technical Architect + Critical Reviewer)

No missed-alarm path reachable by an unauthenticated party. `last_alive` advances only on DataChannel messages of an attempt that passed proof and DTLS check (`attempt.rs:274-281`); both stop paths are bound to a trusted attempt or the peer's confirmed, non-retired session (`link.rs:3191-3200, 3300-3312, 2261-2269`; `envelope.rs:1141-1163`); acknowledge cannot hide level 3 (`ACK_MS` 300 s > 180 s); snooze touches only the parent noise event; `terminal()` is refused once the key ever verified (`link.rs:1581-1590`); mailboxes are closed while verified (`3044-3060`); the Android platform maps only the user's stop to the core `Stop` (`LinkController.kt:565-568`), so an OS kill never yields `peer_stopped`. Sans-IO is clean: no `HashMap`, `SystemTime`, threads or `rand` in `core/src`; SplitMix64 for `aid`s and ChaCha20 for secrets share no state.

## 9. Keeping the setup secure without more ceremony

What already carries the security model and should stay exactly as it is: the sans-IO core with all trust decisions in one place, sealed session-bound envelopes with de-dup after authentication, the parent pin over DTLS, host-bound ICE and ≤ 10 min TURN credentials, Keystore storage with persist-before-send, no-IP-logging proven by a log search, the log canary in simulation and gate, SHA-pinned CI with empty default permissions, per-crate cargo-deny bans and the dependency-count guard.

What to add, in order of leverage:

1. **Close the two silent-failure edges**: A1 (resume path) and W1 (off switch). Both are small and both break a promise the UI makes.
2. **Remove unused attack surface instead of guarding it**: the PSK-less `Session` bypass (K1), protocol v2 in relay and core (R4, K simplify 1), Nostr leftovers (W3), the `relay-stun`/legacy comments. Less code to audit before the alpha tag.
3. **Make the public server's abuse bounds real**: /64 keying and prune-first limiters (R1), TURN caps 2–3 per address with an allocation alert (R2), the secret off the command line (R5), digest pins (R6), the extra denied-peer ranges (R7). All S, all in `docker/public-server/` and `hub.rs`.
4. **Pin the two binaries in the media path** (T3) and implement the release-APK assertions (T4) before the first tag; decide `panic = "abort"` (T2).
5. **Write the threat model once** (D4) and generate the user-facing "what the server sees" text and the device-data table from it (D1, D11). One source, three outputs.
6. **Make the alpha security review a named prerequisite** of `add-android-release` (D5) with this document's open items as its input.
7. **Owner decisions this review cannot make**: the Doze-gap verdict (L2), web distribution at alpha (D9), protocol compatibility wording (D10), Data Safety answers (D1), PC local mode in alpha or beta (scope 2).
